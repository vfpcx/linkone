## 1. 计费规则设置（仓库老板端 · US-TA-04 / R20 / D-P4-4）

### 1.1 背景：本页为「修复 + 升级」

现状「店铺设置 → 计费维度」区块保存的单价从未真实生效（前后端契约断裂，`12-p4-requirements.md` §2.6 活缺陷）。本波将计费规则从店铺设置的混合表单中**独立成页签**，单独保存、单独校验，并引入**规则版本**概念。

### 1.2 规则模型（用户视角）

- 仓库老板可启用 **件·天**、**托盘·天** 两种计费维度，任选其一或并存；启用的维度必须填写单价（元/件·天、元/托盘·天，≥0，最多 4 位小数）。
- 至少启用一种维度才能保存；两种都不勾选时保存按钮置灰并提示「请至少启用一种计费维度并填写单价」。
- 规则为**租户级**：对本仓库全部入驻批发商统一适用（按批发商单独定价、保底费、阶梯价均为后续版本）。

### 1.3 首次设置（关键用户可见口径：生效日 = 首次保存日，不补历史）

- 首次进入且从未设置过规则时，展示空表单 + 引导横幅。
- 首次保存**无需二次确认**（没有「变更」就没有回溯保护问题），保存后规则**自当日起生效**。
- **用户可见说明（页面固定文案，逐字采用）**：

> 「计费规则自保存当日起生效。生效日之前的在库时间不计费、不补出历史账单；生效当月的账单只包含生效日起的费用。」

- 设计意图（内部）：D-P4-4 拍板——首版规则 effective_from=首次保存日，上线前历史月份不补出账。避免对试点仓库既往在库货物追溯收费引发纠纷。

### 1.4 规则变更（R20 回溯保护）

- 已有规则时修改任一维度开关或单价 → 保存前弹**二次确认**（线框见 §8.2），确认后：
  1. **当日起按新规则计费，变更日当天即按新规则**（05 §1.5）；
  2. 历史已出账账单**不重算**；
  3. 当月未出账部分自动**分段计费**：账单明细中同一货品拆分为「变更前段 × 旧单价」与「变更后段 × 新单价」两行；
  4. 全部**在驻批发商**收到站内信通知（话术见 §9）。
- 同一天多次变更：**当日最后一次保存为准**（当日只留一版）。
- 修改后内容与当前规则完全相同：直接提示「规则未发生变化」，不产生新版本、不发通知。
- 页面展示**历史版本列表**（生效起止日 + 各维度单价），供结算员/仓库老板对账时核查「这一段是按哪版价算的」。

### 1.5 与旧「店铺设置」的关系

- 店铺设置页原「计费维度」区块改为只读摘要 + 「前往计费规则页设置」入口；临期阈值留在店铺设置（属批次开关配套，不随规则版本化）。
- 店铺页对外展示的计费维度文案随规则联动，新增「件·天+托盘·天并存」展示态。

## 2. 每日快照与账单生成（用户视角）

### 2.1 每日快照（结算员对账的「底账」）

- 系统**每日凌晨**自动记录前一日每个批发商、每个货品的计费在库件数与占用托盘数（内部：DailySnapshotJob 00:10，快照只存物理量不存金额，金额出账时按当段单价现算——架构 14 §1.2）。
- 用户可见价值：
  1. 账单详情可**按日下钻**——逐日看到「当日计费件数 × 单价 = 当日费用」；
  2. 对账争议时，双方以逐日快照为共同事实基础；
  3. 某日快照缺失时系统自动回补，用户无感。
- **口径说明（详情页帮助文案）**：「每日计费件数按前一日 24:00 的在库量计算：入库、盘盈自次日起计费；出库、退货、盘亏、清库当日仍计费、次日起不再计费；同一天入库又出库不产生费用。」（与 05 §1.2/§1.3 修订版一致，内部为统一回放公式「≤ D−1」。）
- 未设置计费规则期间也有每日快照（只有物理量、没有金额）；设置规则后，此前天数**只可查物理量、不产生费用**。

### 2.2 月度账单自动生成（US-ST-01）

- **每月 1 日凌晨**自动生成上月账单，每（仓库 × 批发商 × 月）一张，重复触发不会生成第二张（幂等）。
- 账单编号：`BL-{仓库简码}-W{批发商编号}-{年月}`，如 `BL-T8801-W17-202607`（月粒度、无日序列，05 §7.1 修订版）。
- 账期：`[max(当月 1 日, 规则生效日), 当月最后一日]`——规则月中才设置的，账单期间从生效日起。
- 生成后状态=**待核对**，站内信通知本仓库全部结算员。
- **已退驻/已下架批发商照常出尾款账单**：上月仍有在库天数就有费用。结算员操作说明固定文案：「批发商退驻当月产生的费用，将在次月 1 日出账，请留意尾款账单。」
- **应收为 0 的账单仍生成，状态直接=已结清**（便于追溯，04 §3.4）。
- 仓库未设置计费规则 → 不出账；结算员工作台展示提醒横幅：「尚未设置计费规则，无法生成账单，请联系仓库老板前往设置。」手动补跑入口同样提示。
- 结算员可**手动补生成**指定月份账单（应对极端的自动生成失败），重复补跑返回既有账单。

### 2.3 账单明细构成（对账下钻）

账单详情提供两个下钻视角（**无「按批次」视角**，D-P4-1 拍板：账单一律按货品（SKU）粒度出账；06 §4.2 原线框的「按批次」选项移除）：

| 视角 | 内容 | 数据来源 |
|---|---|---|
| 按货品 | 每货品一行（月内规则变更时拆分段多行）：计费段起止、件·天、托盘·天、两维单价、小计金额 | 账单仓储费明细行 |
| 按日 | 逐日：日期、当日计费件数、当日占用托盘、当日金额 | 每日快照 + 当段单价现算 |

明细行类型（界面中文名 → 内部枚举）：

| 界面名称 | 枚举 | 说明 |
|---|---|---|
| 仓储费 | STORAGE | 货品 × 规则段，账单主体 |
| 调整 | ADJUSTMENT | 折扣/减免（负值）；以及**跨月回溯差额**（可正可负，见下） |
| 冲销 | REVERSAL | 反向条目，金额=−原条目，关联展示原条目（R10 不删原条目） |
| 盘点影响 | STOCKTAKE_IMPACT | 上月每笔盘盈/盘亏一行，**金额恒 0 纯展示**，说明如「盘盈 +5 件（7-12 审批，次日起算）」「盘亏 −2 件（7-20 审批，当日截止）」——费用本身已含在仓储费行内（US-WK-03 承诺的账单可见性） |

**跨月回溯差额（仲裁恢复/入库纠错落在历史月）**：历史已出账账单一字不改；差额自动生成一条「调整」行进当月账单，说明注明「{历史月} 仲裁恢复/纠错回溯差额」。界面提示文案：「本条为历史月份库存更正产生的费用差额，原账单不变。」（D-P4-2，架构 14 §1.5。）

**账单金额恒等式（页面头部三卡）**：应收 = 仓储费小计 + 调整合计；未收 = 应收 − 已收。任何调整/冲销/回款后三卡实时联动。

## 3. 账单生命周期（6 态流转）

### 3.1 状态中文对照表（界面唯一话术）

| 界面状态 | 枚举（内部） | 进入方式 | 该状态下可做 |
|---|---|---|---|
| 待核对 | DRAFT | 月初自动生成 / 撤回下发后回到 | 结算员：调整、冲销、下发、导出（预览稿）；批发商**不可见** |
| 已下发 | DISPATCHED | 结算员下发 | 批发商：查看、确认、申诉；结算员：撤回（无回款且未确认时）、导出 |
| 待回款 | PENDING_PAYMENT | 批发商确认对账 / 下发满 1 天自动 | 结算员：回款登记、导出；批发商：申诉（窗口内） |
| 部分回款 | PARTIAL_PAID | 回款登记后 0<已收<应收 | 同待回款；另可回款冲销 |
| 已结清 | PAID | 已收=应收 / 应收 0 账单生成即此态 | 结算员：回款冲销（先退状态再改账）、导出 |
| 争议中 | DISPUTED | 仓库老板强制下架批发商（R14）联动 | **全部操作冻结**，仅可查看与导出（见 §7.2） |

### 3.2 流转规则（对齐 04 §1.4 与架构 14 §3.1，产品口径）

```
待核对 → 已下发（下发）
已下发 → 待核对（撤回：0 回款 且 批发商尚未确认）
已下发 → 待回款（批发商确认对账 / 下发满 1 天自动进入）
已下发/待回款/部分回款 → 争议中（强制下架联动）
待回款 → 部分回款 → 已结清（回款登记累计）
已结清 → 部分回款/待回款（回款冲销后回退）
争议中 → （本期无出口，后续版本平台仲裁解冻）
```

- **一致性约束**（04 §6.2/§3.4 原样落地）：
  - 已下发后不能直接改金额——必须先撤回（提示：「账单已下发，请先撤回后再调整」）；
  - 已结清账单要改账——必须先冲销对应回款记录、状态回退后再调整/冲销条目；
  - 撤回时批发商端原账单标记「已撤回」并收到通知。
- **满 1 天自动确认**：账单下发满 1 天批发商未点「确认对账」，系统自动转入待回款（内部：BillAutoConfirmJob 每日 00:50）。下发成功提示语向结算员透出该规则：「已下发给批发商。对方确认后进入待回款；满 1 天未确认将自动进入待回款。」

### 3.3 结算员操作集（对齐架构 14 §3.3）

| 操作 | 前置状态 | 规则要点 | 用户可见约束文案（错误提示对齐错误码表） |
|---|---|---|---|
| 调整（US-ST-02） | 仅待核对 | 类型=折扣/减免，金额>0（入账为负值），原因必填；调整后应收不得为负 | 「当前状态不可调整，请先撤回下发」／「调整金额超出账单小计」 |
| 冲销（R10） | 仅待核对 | 只能冲仓储费/调整行；同一条目只能冲一次；新增反向条目、不删原条目 | 「该条目不可冲销或已被冲销」 |
| 下发（US-ST-03） | 待核对 | 站内信真实送达批发商（短信通道试点期为模拟发送） | — |
| 撤回（R11） | 已下发 | 需 0 回款且批发商未确认 | 「账单已有回款或已被确认，无法撤回」 |
| 回款登记（US-ST-04） | 待回款/部分回款 | 见 §3.4 | 「登记金额超出剩余应收」／「账单已结清，无需重复登记」 |
| 回款冲销（R12） | 回款记录有效 | 理由必填 + 二次确认；状态按剩余已收额回退 | 「该回款记录已冲销或不存在」 |
| 申诉处理 | 申诉待处理 | 结论=成立/不成立 + 处理说明必填 | 「该申诉已处理」 |
| 导出（US-ST-05） | 任意状态 | 见 §6；待核对导出带「未下发预览稿」水印 | — |

全部操作记操作日志（操作人 + 以结算员身份操作；一人多岗时日志按实际所用身份记录，05 §5.2）。

### 3.4 回款登记（线下回款，US-ST-04）

- 字段：本次收款金额（必填，>0，**不得超过剩余应收**——平台不做多收挂账）、收款日期（必填，可选过去日期）、收款方式（必填：银行转账/现金/微信/支付宝/其他）、转账凭证照片（选填，≤5 张）、备注（选填）。
- 支持**多次部分回款**：每次登记一条回款记录，已收金额累加；累计=应收时状态自动转已结清。
- 每次登记后批发商收到站内信（含金额与累计进度）。
- **回款冲销（R12）**：误登/客户退款时对单条回款记录冲销——理由必填、二次确认；冲销后该记录标「已冲销」（保留可见，不删除），已收金额回减，账单状态自动回退到部分回款或待回款；批发商收到通知。

### 3.5 批发商侧：账单接收、确认与申诉（US-WA-08）

- 批发商只能看到**已下发过**的本商户账单（待核对账单不可见；批发商员工整域不可见账单，见 §5.3）。
- 收到「账单已下发」站内信（短信模拟）后，账单页可：
  - **确认对账** → 账单转待回款；确认前展示提示：「确认后请按线下约定方式付款，仓库结算员收款后将登记回款。」
  - **发起申诉**：窗口=**账单下发后 7 天内**；理由必填，可勾选具体争议条目、附图 ≤5 张；同一账单同时只能有一张待处理申诉（提示「该账单已有待处理申诉」）；超窗提示「申诉期已过（账单下发后 7 天内可提）」。
  - **申诉不冻结账单**——账单仍可被确认/回款；是否撤回调整由结算员判断（04 §2.3 口径）。
- 申诉留痕：申诉记录（时间/理由/条目/附件）与处理结论（成立/不成立 + 说明）永久展示在账单详情「申诉记录」区，双方可见。
- 与出库客诉的边界（避免用户混淆，申诉入口带说明）：「对出库货损/数量的投诉请走出库单客诉，此处仅受理账单金额与计费争议。」（D43：出库客诉不改账单。）

## 4. 结算员角色启用（业务面从占位到可用）

### 4.1 角色开通链路（复用已上线能力）

- 仓库老板在「员工注册码」页生成**结算员注册码**（已上线，US-TA-03 链路）；员工扫码注册即绑定本仓库结算员身份。
- 结算员登录后进入**结算工作台**（替换现占位页）：本月账单概览卡（应收/已收/未收）、待处理事项（待核对账单 N 张、待处理申诉 N 张）、快捷入口（账单列表/申诉队列）。
- 一人多岗（如老板兼结算员）：权限并集，进入结算相关页面时操作以结算员身份记日志；界面不展示任何身份代码。

### 4.2 三核心页 + 移动可用（D-P4-9 拍板降档口径）

- 本期不建独立手机端；PC 管理端全功能，其中**账单列表、账单详情（含下钻与操作）、回款登记**三核心页做**响应式适配**，手机浏览器可完成移动场景的全部关键操作（响应式标注见 §8.10）。

## 6. 账单导出（US-ST-05 · D-P4-8 口径）

- 格式：PDF / Excel，点击后**即时生成并下载**（不在服务器留存文件，无历史文件管理）。
- 任意状态可导出；**待核对状态导出的 PDF 加「未下发预览稿」水印**，防止预览稿流出被当正式对账单。
- PDF 版式（正式凭证）：抬头（仓库名 + 账单编号 + 账期 + 批发商名）、三金额汇总、明细行（含分段/调整/冲销/盘点影响行全量）、回款记录、落款区含**印章位**（预留盖章空白框 + 「（仓库盖章处）」字样）与导出时间。
- Excel 版式（对账用）：汇总 Sheet + 明细 Sheet（按货品）+ 按日 Sheet（快照）+ 回款 Sheet。
- 明细超 5000 行时自动降级为按货品聚合导出，文件内注明「明细行数过多，已按货品聚合」。
- 手机端：浏览器直接下载，文件可通过系统分享转发微信（不做应用内分享通道）。
- 批发商端同样可导出本商户已下发账单（同版式，无预览稿场景）。

## 7. 异常与边界场景

### 7.1 R13 · 批发商主动退驻 × 账单结清校验

- 退驻前置自查第 3 项由「本期不校验」占位转**真实校验**：存在任一**未结清**账单（含争议中）→ 不允许发起退驻，提示：「退驻前须结清账单（存在未结清账单）」并展示未结账单数与列表入口。（内部：assertAllSettled，错误码 50323；发起与仓库老板审批双重校验。）
- 自查面板的「账单结清」项由灰色「暂不校验」转真实的 ✓/✗ + 未结张数。
- **尾款提示**（防用户误解「都结清了怎么还有账单」）：退驻确认页与批发商端退驻说明加一句「退驻当月产生的仓储费将于次月 1 日出账，请关注尾款账单」。

### 7.2 R14 · 强制下架 × 争议中账单

- 仓库老板强制下架批发商时，该商户全部**已下发/待回款/部分回款**账单立即转「争议中」，结算员收到站内信；待核对账单不转（尚未对外），但**商户已处于下架状态时新生成的账单直接落「争议中」**。
- **争议中账单的展示与冻结**：
  - 列表/详情状态标签「争议中」（醒目色）+ 详情顶部横幅：「该批发商已被强制下架，账单进入争议状态。争议期间账单冻结，仅可查看与导出；线下协商解决后的处理功能将在后续版本提供。」
  - 冻结范围=全部写操作（调整/冲销/下发/撤回/回款登记/回款冲销/确认/申诉），点击一律提示「账单争议中，操作受限」。
  - **已知取舍（交付纪要标注）**：争议期间线下收到的款项暂时无法登记（D-P4-10 拍板：平台仲裁解冻闭环留后续版本）。
- 批发商端下架后仍可登录查看并导出争议中账单（保留其对账知情权），但同样无法操作。

### 7.3 其他边界（拍板执行要点落成产品口径）

| 场景 | 口径 |
|---|---|
| 应收 0 账单 | 照常生成、直接已结清；列表可查（追溯需要），不发「账单已下发」类通知 |
| 无规则租户 | 不出账 + 工作台横幅提醒（§2.2）；手动补跑提示「计费规则未设置，无法生成账单」 |
| 规则月中生效 | 账期从生效日起；账单头部展示实际账期起止，避免「怎么少算了几天」的疑问 |
| 托盘历史基数 | 托盘·天自规则生效时的现值起算；启用托盘·天时提示先盘点校准（§5，D-P4-5） |
| 盘亏封顶 | 盘点差异被在库量封顶时，账单按实际核减件数展示与计费（12-p4 §2.2） |
| 申诉与撤回并发 | 账单被撤回后，未处理申诉保留待处理（指向原账单），结算员处理时可见「账单已撤回重算」上下文 |
| 月初生成失败 | 单个批发商生成失败不影响其他；结算员次日可手动补生成（幂等） |
| 同名货品展示 | 账单/下钻明细统一展示货品名称+规格（随 L-5 契约补口），不出现仅编号无名称的行 |

## 10. 验收要点汇总（供测试&审查引用）

1. 规则：首存免二次确认、当日生效、历史不补出账（§1.3 文案逐字校验）；变更走二次确认+分段+通知；同日多次变更取最后一次；单价真实落库回显（§2.6 缺陷收口证据）。
2. 账单：月初自动生成/幂等/账期截断；应收 0 直落已结清；6 态流转与冻结约束逐条（§3.2/§3.3 错误提示文案与 `architecture/05-error-codes.md` P4 段一致）。
3. 下钻：按货品（含分段行）/按日（快照）两视角；无「按批次」；盘点影响行金额恒 0；跨月差额行说明可见。
4. 回款：多次部分、不允许超收、冲销回退链路；凭证 ≤5。
5. 申诉：7 天窗、单张待处理、不过冻结账单；处理留痕双向可见。
6. 权限：结算员无库存明细入口；批发商员工账单整域不可见；库管员全拒；跨租户/商户按不存在。
7. R13/R14：退驻未结清拦截提示+自查真值；强制下架三态转争议中+新账单直落争议中；争议中全操作冻结提示。
8. 响应式：三核心页移动视口全流程（§8.11 验收标注）。
9. 导出：预览稿水印、印章位、5000 行降级、移动端可下载分享。
10. 文案：全部用户可见文案零角色码、状态全中文（§4.1 对照表为唯一话术源）。
