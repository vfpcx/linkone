## 0. 文档说明与范围

P3 两条履约异常链的终点都是「仲裁」：

- **入库链**：WA 异议 WK 代建入库 → **TA 仲裁**（裁定异议是否成立、流水是否恢复）；
- **出库链**：WA 对 WK 代建出库不可异议（D43），仅可 30 天内提客诉 → **OPS 仲裁**（仅判责，不改库存与账单）。

按拍板问题三 **选项 B（最小闭环版）**，本 PRD 只定义：**单据引用 + 发起理由 + 附件照片 + 结论枚举 + 结论备注 + 双方站内信通知**。

**明确出圈（→ P5 再议）**：调证流程、多轮沟通/留言、证据补交、赔偿金额追踪、仲裁撤回/重开、同一单据多轮客诉、RT 端客诉入口扩展。平台不接资金（D03/D25），一切结论仅作**线下赔偿依据**。

## 1. Complaint / 仲裁单实体（最小字段集，收口 Q-D04）

> **落库命名对齐**（依据 `architecture/12-p3-design.md` §4 定稿，落库字段以该节为准）：落库表名 **`arbitrations`**，关联单据为多态引用 `ref_doc_type / ref_doc_id / ref_doc_no`；业务/界面上仍称"仲裁单 / 客诉单"。本节字段名即架构定稿名，前端按此开发，勿自造字段。

一张仲裁单（`arbitrations`）承载两个子类型，字段集如下。

### 1.1 公共字段

| 字段 | 说明 | 约束 |
|---|---|---|
| doc_no | 仲裁单号 | 入库异议仲裁 `YY-`、出库客诉 `KS-` 前缀，沿用 05 §7.1 已上线格式（`前缀-{tenant简码}-{YYYYMMDD}-{4位日内序列}`） |
| biz_type | 子类型 | `INBOUND_DISPUTE`（入库异议仲裁）/ `OUTBOUND_COMPLAINT`（出库客诉）——取值以架构定稿词序为准 |
| ref_doc_type / ref_doc_id / ref_doc_no | 关联单据（多态引用） | 入库异议→入库单（WK-）；出库客诉→出库单（CK-）。**一单一诉**：同一单据同类型在途仲裁单仅允许 1 张；已裁决后不可再提（多轮 → P5） |
| tenant_id / wholesaler_id | 归属 | 数据隔离沿用 05 §6 |
| initiator_role / initiator_id | 发起方 | 见 §5 权限 |
| reason | 发起理由 | **必填**，文本 ≤500 字；入库异议弹窗提供预设快捷项（未到货 / 数量不符 / 质量问题 / 其他）填充后可补充说明——两版线框口径以「预设单选 + 其他」为准（顺带收口 08 G1 §5.3c 分歧） |
| attachments | 附件照片 | 选填，≤5 张 / 单张 ≤5MB，存储与分桶复用 05 §11 |
| status | 状态 | `PENDING`（待仲裁）→ `DECIDED`（已裁决），两态最小，不可逆 |
| conclusion | 结论枚举 | 按 biz_type 取值域不同，见 §2 / §3 |
| conclusion_remark | 结论备注 | **必填**（结论是线下赔偿唯一依据，必须留痕） |
| arbitrator_user_id | 仲裁人 | TA（入库）/ OPS（出库） |
| created_at / decided_at | 发起 / 裁决时间 | — |

### 1.2 入库异议扩展字段（差额定责，问题一 B 派生）

仅 `biz_type=INBOUND_DISPUTE` 使用：

| 字段 | 说明 |
|---|---|
| registered_qty | 原代建入库登记件数 |
| reversed_qty | 异议时实际冲销件数（**按当时剩余在库封顶**） |
| shortfall_qty | 已售差额件数 = registered_qty − reversed_qty（异议时刻快照，落单固化） |
| liability | 差额责任方，枚举 `WK_LIABLE / WA_LIABLE / NEGOTIATED / NO_LIABILITY`；**仅当 conclusion=REJECTED（驳回·保留冲销）且 shortfall_qty>0 时必填**（此时已售部分是"不该存在的货"，须定责供线下赔偿）；conclusion=APPROVED（通过）时该字段不适用（货真入库，已售部分属正常销售） |

### 1.3 流转（状态机）

```
[*] → PENDING（发起即生成，通知双方+仲裁人）
PENDING → DECIDED（仲裁人提交结论，通知双方）
不可达：DECIDED → PENDING ❌（重开 → P5）
```

### 1.4 通知（双方站内信，最小版不发短信）

| 触发 | 接收方 | 内容要点 |
|---|---|---|
| 仲裁单创建 | 对方当事人（租户侧 WK/TA 或 WA 侧）+ 仲裁人待办计数 | 单号、关联单据、理由摘要 |
| 裁决完成 | 发起方 + 对方当事人 | 结论枚举 + 结论备注 +（如有）差额定责结果 |

幂等要求沿用 04 §6.4。

## 2. 入库异议 · TA 仲裁

### 2.1 触发与前置

- WA（或被授权 WE，授权位 `INBOUND_CONFIRM`，G7）对 `source=wk_created` 且状态=待WA确认 的入库单，72h 窗口内提出异议（US-WA-09，既有）。
- 异议提交瞬间系统即时冲销 + 自动生成本仲裁单，入库单转「争议中」（04 §1.1 既有）。

### 2.2 冲销规则（问题一 B）

- **冲销按剩余在库封顶**：登记 30 件、已售 20 件 → 只冲销在库 10 件；`reversed_qty=10, shortfall_qty=20` 固化进仲裁单。
- 边界：异议时在库=0 → 冲销 0 件，仲裁单照常生成（全部为差额）；在库=登记数 → 经典全额冲销，无差额。
- 已售出部分的出库流水**不受任何影响**（货已离仓不可逆）。

### 2.3 结论二选与联动

| 结论（conclusion 架构码值） | 语义 | 入库单状态 | 库存/流水联动 |
|---|---|---|---|
| **通过 · 恢复流水**（`APPROVED`） | 异议不成立，入库有效 | 争议中 → 已确认 | 生成恢复流水，件数=reversed_qty，**沿用原入库时间戳**（见 §2.4） |
| **驳回 · 保留冲销**（`REJECTED`） | 异议成立，入库无效 | 争议中 → 已撤销 | 无库存变化（冲销保留）；shortfall_qty>0 时必填差额定责（liability），线下赔偿 |

> 术语对齐 04 §1.1：「仲裁通过」= 恢复流水（判入库有效）；「仲裁驳回」= 保留冲销（判异议成立）。前端文案须写全「通过·恢复流水 / 驳回·保留冲销」防歧义。

### 2.4 计费语义标注（G10 口径，P3 只标注、P4 回溯，不算金额）

| 流水 | 类型（名称架构定） | 计费语义字段 |
|---|---|---|
| 异议冲销流水 | DISPUTE_REVERSAL | 截止=异议日（当日含），与 05 §4.2 既有口径一致 |
| 仲裁恢复流水 | DISPUTE_RESTORE | `effective_at` = **原入库时间戳**（拍板问题三 B 备注）；另带标注字段 `billing_anchor=ORIGINAL_INBOUND_AT` + `restored_from_inbound_at` 供 P4 回溯 |

P4 回溯的账面效果：该批货自**原入库次日 0:00 起连续计费、无中断**（冲销/恢复流水成对抵消，争议期间照常计费）。P3 交付边界：保证流水**时间戳、类型、锚点字段**准确可回溯即可，不实现任何金额计算（08 §7.6）。

### 2.5 SLA

最小版不设硬性裁决时限；仲裁单进 TA 审批中心待办计数，超 72h 未裁在列表标「⏰ 超时」提醒（纯展示，不自动流转）。硬 SLA/升级 → P5。

## 3. 出库客诉 · OPS 仲裁

### 3.1 触发与前置（既有规则汇总）

- 仅 `source=wk_created` 且状态=已出库 的出库单；WA 发起。
- **30 天窗口**：自实际出库时间起 720h 内可提；超时入口置灰并提示「已超过 30 天客诉期」。
- 提诉后出库单 已出库 → 客诉中（04 §1.2 既有）。

### 3.2 结论四选（05 §4.2 既有枚举）与联动

| 结论 | conclusion 码值 |
|---|---|
| WK 责任 | `WK_LIABLE` |
| WA 责任 | `WA_LIABLE` |
| 双方协商 | `NEGOTIATED` |
| 无责 | `NO_LIABILITY` |

- **仅判责，不改库存、不改账单**（D43）；裁决后出库单 客诉中 → 已出库。
- 结论 + 备注推送双方站内信，作为线下赔偿依据。
- 「客诉中」单据计入退驻前置校验的「未结单据」（R13，P2 口径），须裁决后才可退驻。

## 6. 产品文案规则（问题一 B 强制透出）

1. **全局口径文案**（WK 代建入库二次确认弹窗、WA 待确认队列头部、异议弹窗均需展示）：
   > **代建入库即视为可售，72 小时内可提异议，异议仅覆盖仍在库部分；已售出部分将进入差额定责。**
2. **异议弹窗实时数字**：提交前必须展示「登记 N 件 / 当前在库 M 件（将冲销）/ 已售 N−M 件（将进入差额定责）」，且差额 >0 时强制二次确认。
3. TA 仲裁结论按钮文案写全：「通过·恢复流水」「驳回·保留冲销」；OPS 结论弹窗固定注脚「仅判责，不改库存与账单」。

## 7. 依赖与实施标注（给架构/开发）

- **调度**：72h 自动确认 job 复用 Wave2 已落地的 `SchedulingConfig` 基建（`com.cangchu.common.config.SchedulingConfig`，同 60 天归档 job），不再选型。
- **单据号**：YY-/KS- 前缀走既有 `DocumentNumberService.generate`（4 位日内序列、日切 TTL），见修订后的 05 §7.1。
- **流水原则**：冲销/恢复一律新增独立流水，禁止 update 原流水（D22 同构）。
- **Flyway**：P3 迁移自 **V15** 起（09 修正二），各波开工前再核 main 最高版本。
- **错误码**：建议 document 异常链取 50320+ 段（08 §7.1 建议），最终由架构定稿。
- **OPS 前端**：路由守卫查角色已在 feat/p2-onboarding-fe 修复，客诉中心按 §4.2 从工作台「客诉单」计数卡下钻。
