## 0. 文档说明

补齐 `06-page-wireframes.md` 产品设计缺口 #1 的 6 个入驻生态页面：ASCII 线框 + 字段清单（必填/校验）+ 交互说明（按钮态/弹窗/错误态/空态）+ 异常场景。

视觉 token / 组件规范仍归 [`shared/design-system/MASTER.md`](../design-system/MASTER.md)（状态徽章用 §4.6、弹窗用 §4.4、表格用 §4.2、时间线用 §4.10）。图例同 06 §0。

**已定决策直接落图，不再另开方案**：

| 决策 | 体现位置 |
|---|---|
| O-2 黑名单拦截 OPS 代建 | §5 黑名单页命中记录含"OPS 代建"来源；OPS 代建表单命中 50205 同样拦截 |
| O-4 WE 最小授权两枚（PRICE_EDIT / INQUIRY_CONFIRM） | §6 生码弹窗与员工列表只出现这两个授权位 |
| O-5 账单结清校验 P4 占位 | §3 退驻自查清单第 3 行显示"本期不校验" |
| 错误码 50201 审核中 / 50202 已退驻 / 50205 黑名单 | §1 / §3 错误态 |

**权限对齐（01 §4.2）**：入驻申请=WA ✅ / WE ❌；入驻审批=TA ✅（OPS ❌）；封禁下架=OPS ✅ + TA ✅本店；黑名单=OPS 专属；员工码生成=WA ✅本商户 / WE ❌。无权角色**不渲染入口**（同 01 §6.5 原则）。

状态机（04 §1.8）快照，本文所有状态字样以此为准：

```
待审核 → 已驳回 | 正常(已通过)
正常 → 已下架(R14, 不可原地恢复) | 已退驻(R13, 需TA审批)
已退驻 → 正常(60天内恢复) | 归档(60天后)
不可达：已退驻→已下架 ❌；已下架→正常 ❌
```

### 1.2 字段清单

| 字段 | 必填 | 校验 | 说明 |
|---|---|---|---|
| 目标仓库 | * | 必选；下拉只列"正常"状态且开放入驻的仓库 | 广场进入/注册带入时锁定只读 |
| 商户名称 | * | 2~30 字符；同仓库内商户名重复时提交报错提示改名 | |
| 联系人 | * | 2~20 字符 | 默认带入注册真实姓名 |
| 联系电话 | * | 11 位手机号格式 | 默认带入注册手机号，可改；黑名单双键之一 |
| 营业执照号 | 选填 | 填写时校验 18 位统一社会信用代码格式 | 黑名单双键之二；与 06 §1.4 OPS 代建保持同为选填 |
| 资质照片 | 选填 | ≤3 张，单张 ≤10MB，jpg/png | |
| 备注 | 选填 | ≤200 字符 | |

### 1.3 交互说明

- **提交按钮**：必填未齐 → 置灰 + 未填字段红框（同 01 §6.4 兜底惯例）；点击后 loading 态防重复提交；成功 → 跳 1.4 待审核状态页。
- **一账号一仓（01 §3.5）**：当前账号已有"正常"入驻 → 本页不可达，入口处直接显示"您已入驻 XX 海鲜库"；已有"待审核"申请 → 打开本页直接落到 1.4 状态页。
- **空态**：目标仓库下拉无可选仓库 → "暂无开放入驻的仓库，去仓库广场看看 [前往]"。

### 1.5 错误态与异常场景

**黑名单命中（50205）— 提交时弹窗**：

```
┌─────────────────────────────────────┐
│ ⚠️  无法提交入驻申请                  │
│ 您的账号信息暂不符合平台入驻条件。   │
│ 如有疑问请联系平台客服。             │
│ (错误码: 50205)                      │
│              [知道了]                │
└─────────────────────────────────────┘
```

※ 文案**不提"黑名单"字样、不透出命中键**（防试探规避），仅露错误码供客服核查。表单不清空，用户可联系客服后再试。

| 场景 | 处理 |
|---|---|
| 已有申请审核中（50201） | 提交报错 → toast"您已有一笔申请审核中" + 自动跳 1.4 待审核页 |
| 账号处于已退驻（50202） | 表单顶部黄条"您在 60 天恢复期内，可直接恢复原入驻 [去恢复]"（跳 §3.4），仍允许对**其他仓库**提交新申请 |
| 目标仓库审核期间被冻结/下线 | 状态页顶部灰条"该仓库暂不可入驻，申请已自动关闭"，提供 [重新选择仓库] |
| 网络失败 | 表单本地暂存，恢复后提示 [继续提交] |

### 2.3 交互说明与异常

- [通过] / [确认驳回] 点击后 loading 防重；成功 toast + 列表行即时刷新并移出"待审核"Tab。
- 驳回理由为空或 <5 字 → [确认驳回] 置灰 + 输入框下红字提示。
- **仅 PENDING 可审**（复用 tenant audit 惯例）：他人已先审完 → 报错弹窗"该申请已被处理，列表已刷新" + 自动刷新。
- 空态：待审核 Tab 空 → "暂无待审核的入驻申请"。
- 权限：本页仅 TA 可见（01 §4.2 入驻审批 TA ✅）；WK/ST 无菜单项。
- H5 适配（TA 备用端）：列表转卡片流，[审] 弹窗改全屏面板，其余同 PC。

| 对其他仓库发起新申请时命中 50202 | 见 §1.5：50202 仅拦"恢复原仓库前重复申请原仓库"，其他仓库放行 |

### 4.2 交互说明

- **[确认强制下架] 双条件解锁**：下架原因 ≥5 字 **且** 输入框内容与商户名完全一致（大小写/空格敏感，实时比对，不一致时输入框下灰字"名称不一致"）。
- 按钮为危险色（红），点击后 loading；成功 toast"已强制下架" + 列表行状态变 ⚫已下架，操作列只剩 [详情]（**无恢复按钮**——已下架→正常不可达）。
- 商户侧联动：WA/WE 新业务请求被拒；收到站内信+短信；WA 端首页顶部红条"本店已被仓库强制下架，进行中的出库单可继续完成，如有疑问请联系仓库或平台客服"。

### 4.3 异常场景

| 场景 | 处理 |
|---|---|
| 目标商户状态已不是"正常"（并发） | 报错弹窗"商户状态已变化，请刷新" |
| 商户存在进行中出库单 | 不阻断（老单据放行）；弹窗内"允许完成"行动态显示计数："已确认意向单 2 / 已生成出库单 1 允许完成" |
| 对已退驻商户点强制下架 | 入口不出现（已退驻→已下架不可达） |
