## 一、T1 · 正向申请链（批发商主动入库申请）

### 1.1 状态流转（用户视角）

```
[新建] → 待受理 → 已受理 → 已入库（终态）
            ├→ 已撤回（终态，发起方撤回，理由必填）
            └→ 已驳回（终态，库管员驳回，可一键复制重建）
```

| 界面状态 | 枚举（冻结） | 触发人 | 库存/计费影响 | 此状态下可用操作 |
|---|---|---|---|---|
| 待受理 | SUBMITTED | 批发商管理员 / 被授权批发商员工 提交 | **零影响** | 发起方：撤回（R1，理由必填）；库管员：受理 / 驳回 |
| 已受理 | ACCEPTED | 库管员受理（**锁单**） | 零影响 | 库管员：登记入库、打印核对单；发起方：**不可撤回** |
| 已入库 | CONFIRMED | 库管员登记 | **此刻加库存 + 入库流水**；计费次日 0:00 起算 | 补打入库单；库管员 ≤24h 可发起纠错（R3） |
| 已驳回 | REJECTED | 库管员驳回（R2） | 零影响 | 发起方：一键复制重建新申请 |
| 已撤回 | WITHDRAWN | 发起方撤回（R1） | 零影响 | 无（可另行新建） |

关键口径：

1. **入库 = 登记才加库存**（与出库「创建即扣」有意不对称，均为 PRD 原文）：待受理/已受理期间库存、计费零变化。前端在申请详情固定展示说明文案：「提交与受理不影响库存与计费，货物登记入库后次日开始计费」。测试断言禁止拿出库口径套入库。
2. **终态命名（D-3）**：登记直接落 CONFIRMED，不复活第三个同义终态；与代建链共用 CONFIRMED，靠 source（批发商提交 / 仓库代建）区分链路，界面文案统一「已入库」。正向链不经过「待批发商确认」（自己提的申请无需自我确认），72h 自动确认任务天然不命中。
3. **不可达红线**：已驳回 → 已受理 ❌；已入库 → 已撤回 ❌（05 §4.1）。并发受理/撤回撞车按既有状态机错误提示（「单据状态已变化，请刷新后重试」）。

### 1.2 批发商提交入库申请（表单）

入口：批发商端「入库」页 [+ 新建入库申请]（批发商管理员默认可见；批发商员工需授权，见 §1.8）。**无语音入口**（D-1 推 P5）。

| 字段 | 必填 | 交互 |
|---|---|---|
| 入库仓库 | — | 固定为当前入驻仓库，只读展示 |
| 商品行（可多行） | ≥1 行 | 每行 = SKU + 申请件数 + 占用托盘数 |
| ├ SKU | ✅ | **弹窗选择器 + 远程搜索**（本商户 SKU，含已下架标识；列表项：SKU 名 + 规格摘要） |
| ├ 申请件数 | ✅ | 正整数 |
| ├ 占用托盘数 | 选填 | 非负整数，默认空 |
| ├ 批次号 / 生产日期 / 到效期 | T4 前隐藏 | 批次开关启用后按 §3.2 分支显示 |
| 照片附件 | 选填 | ≤5 张挂单据（D-2 最小版：仅附件留证，不入相册、不联动展示图） |
| 备注 | 选填 | ≤200 字 |

**多行拆单（D-5）**：表单支持多商品行；提交时**按行拆成 N 张一单一 SKU 的入库申请**，共享同一「提交批次号」（batch_submit_id）。提交前弹确认：「本次将生成 N 张入库申请单（每商品一单），仓库可分别受理」。列表与打印支持按提交批次聚合展示/聚合打印。

校验与异常：

| 场景 | 处理 |
|---|---|
| 商户已下架（R14） | 提交按钮禁用 + 顶部提示条「商户已下架，暂不可提交入库申请」 |
| 件数为 0 / 非法 | 行内红字校验，提交置灰 |
| 附件超 5 张 / 超 5MB | 上传即时拦截提示 |

### 1.3 我的申请列表与撤回（R1）

- 列表 Tab：全部 / 待受理 / 已受理 / 已入库 / 已驳回·已撤回；卡片展示：单号、SKU 名、申请件数、状态 tag、提交时间、同批标识（「同批 N 单」）。
- **撤回**：仅「待受理」可撤；弹窗理由必填（≤100 字）；撤回不影响库存/计费。已受理后撤回入口隐藏，详情页提示「仓库已受理，如需取消请联系仓库」。
- **已驳回详情**：展示驳回原因（单选项中文）+ 备注 + 驳回照片；[一键复制重建] 带出原字段生成新表单。

### 1.4 库管员待受理队列与受理

- 库管员端「入库」Tab 增加「申请待受理」列表（与代建链队列并列）；卡片：单号、批发商名称、SKU 名、申请件数、托盘数、提交时间、同批标识、[受理] [驳回]。
- **受理即锁单**：状态变「已受理」，发起方不可再撤回；受理无需填写内容，一次点击完成（含二次确认弹窗：「受理后批发商将不可撤回，确认受理？」）。

### 1.5 驳回（R2）

驳回弹窗（待受理状态下）：

- 驳回原因 **单选必填**：( ) 数量不符 ( ) 质量问题 ( ) 批次不符 ( ) 其他
- 备注 **必填**（≤200 字）；照片 选填 ≤5 张（复用附件上传）。
- 驳回后通知发起方；发起方端提供 [一键复制重建]。

### 1.6 登记入库（含数量差异边界）

登记页（已受理状态下）字段：SKU（只读）、**申请件数（只读）**、**实际入库件数（必填，默认=申请件数）**、占用托盘数（可改）、照片（选填 ≤5 张，D-2 最小版）、差异备注（条件必填，见下）。

**数量差异边界（04 §3.1）**：

| 差异 | 行为 |
|---|---|
| 实际 = 申请 | 直接登记 |
| 差异 ≤5% | 允许登记，**差异备注必填**；页面黄条提示「实际与申请差 N 件（X%），已按实登记」 |
| 差异 >5% | **禁止登记**，红条提示「差异超 5%，请驳回后由批发商重新提交」，登记按钮置灰，仅可走驳回 |

- 单据**同时保留申请件数与实登件数**两值，详情/打印/通知均双值展示。
- 登记成功：加库存 + 入库流水（业务时间=登记时刻），计费次日起算；状态「已入库」。
- **打印非状态节点**：登记前可打（核对/签收）、登记后补打（盖章存档）；落 printed_at / print_count 列，不产生状态流转；模板复用 design-system/print-templates，支持按提交批次聚合打印。

### 1.7 登记纠错（R3）

- **适用范围**：仅批发商提交的正向链「已入库」单据（代建链错误走既有异议链或盘点，不入纠错）；同一单据在途纠错至多一张（重复发起拦截提示「该单已有待审批的纠错申请」）。
- **窗口**：登记完成后 ≤24h，库管员在入库单详情发起纠错；超 24h 入口置灰，提示「已超过 24 小时纠错窗口，请通过盘点调整」。
- **表单**：原实登件数（只读）→ 更正后件数（必填）、纠错理由（必填 ≤200 字）、照片选填。系统自动计算差额并预览库存联动。
- **审批**：提交后进入租户管理员「单据审批中心」（复用 06 §2.3 审批弹窗样式）；通过后生效，驳回则原单不变（可在窗口内重新发起）。
- **库存联动（D-4，独立流水）**：
  - 件数改大：补录差额 → CORRECTION_IN 流水（+差额）；
  - 件数改小：冲销差额 → CORRECTION_OUT 流水（−实际冲销量）；**遇已售按剩余在库封顶**：实际冲销量 = min(纠错差额, 当前在库)，不足部分**不打负**，差额自动写入纠错单备注（「纠错差额 X 件，其中 Y 件已售出无法冲销，责任线下认定」）并通知租户管理员与批发商管理员。
  - 流水件数恒为正、方向由类型表达；关联原入库流水；业务时间 = 原入库时间戳（P4 按配对重算计费，本波零金额——G10 锚点）；托盘按原单比例联动（释放侧封顶，见 §2.3）。
  - 纠错生效后单据可见件数更新为更正值，原值在纠错单留痕；纠错单为内部审批件，不占单据号前缀。
- 审批弹窗需展示：原值 → 新值、差额、封顶预览（当前在库不足时红字「将按剩余在库 Y 件封顶冲销」）、通过后联动说明。

## 二、T3 · 退货（RTN-）/ 盘点（PD-）

### 2.1 退货单（RTN-）

**状态机**（无审批）：

```
[发起] → 待受理 → 已受理 → 已退货（终态）
            └→ 已撤回（终态，发起方仅待受理可撤）
```

**核心口径**：

| 项 | 口径 |
|---|---|
| 发起 | 批发商管理员（**批发商员工不开放**，D-9；入口对员工隐藏，P5 与出库授权位一并议） |
| 扣库存时点（D-7） | **登记时扣**：待受理/已受理期间货仍可售、库存零变化；库管员现场出货并登记的瞬间扣件数+释放托盘、生成退货流水 |
| 登记时库存不足 | 拒绝登记（复用库存不足错误提示），页面提示「当前在库 N 件不足退货 M 件，请联系批发商修改退货单」；批发商撤回后改单重提（与 04 §3.2 拣货不足同构） |
| 计费 | 业务时间=登记日，仓储费**当天截止**（05 §1.2） |
| 数量校验 | 发起时：退货件数 ≤ 当前在库（前端实时 + 后端软校验提示，不锁定库存）；SKU 选择器仅列在库 >0（05 §14b.10），列表项「SKU 名（在库 N 件）」 |
| 登记按实覆写 | 登记时可按实际出货件数覆写申请件数（备注留痕），登记完成通知含实退件数 |
| 批次 | 批次字段本波隐藏；D-11=C 下退货按 SKU 池登记，指定批次退货随方案 A 顺延 P5 |
| 商品行 | 一单一 SKU（与入库/出库先例一致）；多商品分次发起 |
| 托盘 | 登记页展示默认释放托盘数（§2.3 公式），库管员可覆盖 |
| 与意向单 | 退货不影响任何意向单流转 |
| 通知 | 发起→库管员；登记完成→批发商管理员（含实退件数、释放托盘）；撤回→库管员 |

### 2.2 盘点单（PD-）

**状态机**：

```
[新建] → 草稿 → 待审批 → 已通过（终态，不可逆）
          ↑         └→ 已驳回 →（改正后）草稿重提
          └ 草稿可删除
```

**核心口径**：

1. **系统数 = 账面库存**（已扣后）。已确认未出库的出库单件数已从账面扣除但货仍在仓——**实物 > 账面是正常现象，不是盘盈**。
2. **在途提示条（必做）**：盘点录入页与审批弹窗顶部展示「当前存在 N 张已确认未出库单据（合计 M 件）」（按商户+SKU 聚合）；差异列旁标注「其中 ≤M 件可能为在途出库占用」。**同理提示已受理未登记的退货单**（D-7 登记时扣，已受理退货尚未扣账）。
3. **差异 = 实物数 − 账面数，系统不做在途还原折算**；操作规程建议「无在途作业时段盘点」，提示条即防误判护栏。
4. 差异不设阈值（差异即差异）；是否提交由库管员决定，**租户管理员全量审批**（D23，无自动通过）。
5. **盘亏封顶（D-10，收口 G9）**：审批通过时若某行盘亏件数 > 当时剩余在库，按**剩余在库封顶**生成盘亏流水，差额自动写入盘点单备注并站内信通知租户管理员与库管员（「盘亏 X 件，审批时在库仅 Y 件，已按 Y 件生效，差额 Z 件请线下核查」）；审批弹窗实时预览封顶结果。不采用驳回重盘。
6. **流水与计费**：盘盈 GAIN(+) / 盘亏 LOSS(−) 独立流水，不改原流水（D22）；业务时间=审批通过日——盘亏当日截止、盘盈次日起算（视同当日入库，05 §1.2）；月度账单明细行 P4 交付，本波零金额。
7. **批次分支隐藏**（D-11=C）：盘点**始终按 SKU 总数盘**；D24（盘盈必填批次/盘亏指定批次）随方案 A 顺延 P5。
8. 不生成赔偿单（D25），差异线下协商；单据留痕：操作人/审批人/每行 账面数·实物数·差异/理由/照片（选填 ≤5 张）。
9. 多行：一张盘点单可含多个 SKU 行（弹窗选择器逐个添加、同单 SKU 不重复；账面数自动带出并以**提交时刻**快照定格——提交后的出库不改变差异值，生效量以审批时刻在库封顶，两时点语义分离）。
10. **同商户在途盘点单至多一张**（存在草稿/待审批盘点单时不可再建，提示「该商户已有进行中的盘点单」，防双重盈亏）。
11. 并发：审批生成流水时对涉及 (商户, SKU) 加现有库存锁，与出库/冲销串行化（04 §6.1 降级先例）。
12. 通知：待审批→租户管理员；通过（含封顶差额）/驳回→库管员。

### 2.3 托盘释放口径（D-8=A：T3 波一次补齐）

出库链现状「只增不减」在本波一次性补齐，避免 P4 托盘·天计费虚高：

| 项 | 口径 |
|---|---|
| 适用流水 | **出库、退货、盘亏、临期清库** 四类登记/审批生效时均落托盘变化（盘盈可选填增加托盘） |
| 默认值公式 | 池化近似（05 §3.3 批次关闭分支）：`默认释放托盘 = ceil(该 SKU 当前占用托盘数 × 本次变动件数 ÷ 变动前在库件数)` |
| 覆盖 | 登记页/盘点提交页展示默认值为**提示值**，库管员可手动覆盖为 0～当前占用托盘任意整数（应对托盘未腾空）；审批类单据（盘点/清库）审批弹窗展示最终值 |
| 封顶 | 释放数 ≤ 当前占用托盘数，托盘账**不打负** |
| 全出清零 | 变动后在库件数 = 0 时，默认释放 = 当前占用托盘全部 |
| 历史 | 存量历史流水不回溯补托盘（无覆盖值无法追溯，回填近似值会污染计费基线）；既成的历史托盘虚高由**上线后首次盘点的托盘现值校准**一次性拉平（该操作规程随前端上线说明发布，13 §2.4-4） |
| 出库侧补齐 | 出库登记页新增「释放托盘」字段（默认值+可覆盖）：件数仍创建即扣不变，**托盘在登记出库时释放**（货离仓的物理时点）；登记前撤回从未释放托盘，无需回补 |

## 三、T4 · 批次登记 + 临期预警 + 强制清库（QK-）

> 总纲（D-11=C）：**批次登记 + FIFO 离线推算**。库存交易路径（出库扣减/冲销/回补）零改动、仍按 SKU 池；批次是「登记簿」——记录每批入库量与保质期，每日离线推算剩余，驱动临期预警与强制清库。指定批次出库、批次级盘点、批次级计费下钻随方案 A 顺延 P5。US-TA-12 与 05 §2 已出降级修订版（2026-07-30）。

### 3.1 批次总开关（租户管理员）

| 项 | 口径 |
|---|---|
| 默认 | 关闭；**T4-W1 上线前禁改**（D-13 防御随 T3 任一波落：店铺设置接口拒绝该字段变更，前端开关置灰并提示「批次功能开发中」；存量值校准归 0；T4-W1 解除） |
| 关 → 启 | 弹窗确认「将为现有库存生成默认批次占位」；系统为每个在库 >0 的 SKU 生成默认批次 `DEFAULT-{YYYYMMDD}`（保质期空，批发商管理员可后续补录到效期）；新入库走批次登记 |
| 启 → 关 | 弹窗确认「批次登记簿将冻结，临期预警停用」；全部非终态批次标「已冻结」（登记簿冻结、停止推算与新预警）、入库批次字段隐藏；已生成的清库单继续走完；**无**「老批次独立库存出完为止」问题（库存本就未拆行）；再次启用时生成**新**默认批次，不复活已冻结批次 |
| 频次 | 24h 内 ≤2 次；进行中单据按提交时策略走完 |
| 展示图联动 | 「入库实拍」联动依赖拍照全链（D-2 后置波），本波不做 |

### 3.2 批次登记（入库表单分支）

批次开关=启用时，正向申请表单（§1.2）、库管员登记页与现场代建入库表单显示批次字段：

| 字段 | 必填 | 校验 |
|---|---|---|
| 批次号 | ✅ | (商户, SKU, 批次号) 唯一；重复时拦截并提示「该批次号已存在，请更换」（登记簿一批一行，不做合并，避免归属歧义） |
| 生产日期 | ✅ | ≤ 今天 |
| 到效期 | ✅ | > 生产日期 |

- **过期强警告**：到效期 ≤ 今天 → 弹窗强警告，库管员二次确认后方可登记（04 §3.1）。
- **临期警告**：到效期 − 今天 ≤ 阈值 → 黄条警告但放行，入库后立即进入临期列表。
- 关闭档：字段整体隐藏，仅件数+SKU 校验。
- 落点：批次写入登记簿（批次累计入库、到效期、状态）；入库/清库流水落批次标识，出库流水不落。

### 3.3 FIFO 离线推算（展示口径）

1. **推算规则**：每日 02:00 任务纯读流水，对每个 (商户, SKU) 将出库/退货/盘亏等累计净出量**沿批次先入先出序逐批扣抵**（到效期 → 首次入库时间 → 批次序，无到效期的垫底），得出各批次**推算剩余**；不进交易路径、不加锁、幂等重跑。
2. **启用时点切割**：开关启用前的历史库存被默认批次一次性吸收（默认批次登记量 = 启用时刻该 SKU 池内数量快照）；推算只统计**启用之后**的无批次流水（以启用时间戳切割，13 §3.2），避免历史重复扣抵。
3. **展示统一标注**：所有批次剩余数旁标「推算值 · 截至今日 02:00」；说明气泡「批次剩余按先入先出离线推算，可能与实物有 ≤1 天误差，清库以现场核数为准」。批次合计与该 SKU 账面数的差额在下钻页展示为「无批次在池量」独立行（盘盈未摊完/回补时序所致），不报警。
4. **消费方**：临期预警件数、待清理件数、清库单默认件数、批次下钻页剩余，均以推算剩余为准；推算剩余=0 的批次状态转「已售罄」，不再产生预警。
5. **批次状态**（登记簿）：在库 → 临期（02:00 判定）→ 待清理（02:30 到期归零标记）→ 已清库（清库单通过）；任一阶段推算剩余归 0 → 已售罄；启→关 → 已冻结。
6. 指定批次出库下拉隐藏（05 §2.4 顺延 P5）；出库拣货页不展示批次级 FIFO 建议（05 §2.2 池化口径全局适用）；出库流水不落批次标识。

### 3.4 临期预警与通知（D-12 收口 Q-D06）

| 项 | 口径 |
|---|---|
| 判定 | `到效期 − 当日 ≤ 阈值`（租户管理员设置，默认 30 天）；每日 02:00 扫描（推算剩余 >0 的批次） |
| 自动通知 | 仅对**新进入临期态**的批次发一次站内信（库管员、批发商管理员各一条）；状态不变**不重发**；不发短信 |
| 手动通知 | 库管员临期列表 [通知批发商]：同一批次 24h 限 1 次，超限按钮置灰显示剩余冷却时间 |
| 库管员列表 | 按剩余天数升序；Tab：临期 / 待清理 / 已清库；卡片含推算剩余标注 |
| 批发商端 | 首页临期卡（N 个批次临期）→ 下钻批次列表；收到通知可降价/主动退货/不动作（业务动作走既有链路） |
| 租户管理员 | 临期看板（§3.6-A）总览临期占比与清库待办，决定接货策略（05 §9.2） |

### 3.5 强制清库单（QK-，D-6 并入 T4）

**触发**：每日 02:30 任务扫描 `到效期 − 当日 ≤ 0` 且推算剩余 >0 的批次 → 标「待清理」→ 库管员从临期列表发起清库单。

**状态机**（完全套用盘点）：`草稿 → 待审批 → 已驳回(→草稿重提) | 已通过（终态）`。

| 项 | 口径 |
|---|---|
| 表单 | 一单一批次；批次信息只读（批次号/SKU/商户/到效期/过期天数/推算剩余）；清库件数默认=推算剩余，库管员**现场核数可改**（≤ 该 SKU 池当前在库）；清库原因单选必填（与 13 §3.4 枚举对齐）：( )过期 ( )损坏 ( )其他——选「其他」时备注必填（客户投诉等写入备注）；**实物照片必填 ≥1 张（≤3 张），不受拍照开关影响**；备注选填 |
| 前置 | 仅「待清理」且推算剩余 >0 的批次可发起；同一批次在途清库单至多一张 |
| 审批 | 租户管理员，复用盘点审批弹窗样式；通过时按 SKU 池剩余在库封顶（同 D-10 口径），差额写备注 |
| 生效 | 生成临期清库流水（扣 SKU 池件数、释放托盘按 §2.3、落批次标识、批次推算剩余清零、状态「已清库」）；业务时间=清库日，仓储费**当日截止**；**不计入正常出库统计**，不影响批发商销售数据 |
| 通知 | 待审批→租户管理员；通过→批发商管理员（站内信**含照片凭证**）+库管员；驳回→库管员 |

### 3.7 T4 验收要点

1. 开关：禁改防御（T4-W1 前拒改+提示）→ 解除；关→启默认批次生成；启→关冻结；24h≤2 次；弹窗文案按修订版。
2. 批次校验：唯一约束、过期强警告二次确认、临期警告放行、生产/到效期逻辑校验。
3. 推算任务：多批次先入先扣、出清转态、误差口径展示标注；预警仅新进临期发一次不重发；手动通知 24h 冷却。
4. 清库：待清理标记、件数封顶、照片必填（不受拍照开关影响）、清库流水计费当日截止且不计出库统计、凭证随通知送达。
5. 顺延项回归：指定批次出库入口全隐藏；盘点无批次分支；出库流水不落批次。
